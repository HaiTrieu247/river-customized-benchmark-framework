# conf_pipeline

Online tuning and benchmarking of `river.cluster` in one pass. Every (algorithm, fold, seed) runs on one driver under four tuning regimes (*arms*): `default` (River's defaults, never changed), `confstream` (a confStream ensemble that re-picks its configuration by silhouette after every window), `random_online` (the same ensemble, children drawn uniformly) and `frozen_prefix` (tunes until window `FREEZE_AFTER_WINDOW`, then keeps its incumbent). A Sobol sweep of fixed configurations picks a static oracle per (algorithm, fold), which is rerun as a fifth arm, `oracle_static`, to give the ceiling. Every quality number is the lagged ARI: the incumbent named after window t-1, scored on window t.

Run from the framework root (`--dry-run` lists the jobs; every protocol constant is a flag, see `--help`):

```bash
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.run --algos DenStream,CluStream --folds covtype,k_drift --seeds 1 --workers 8 --log-members --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.sweep --algos DenStream,CluStream --folds covtype,k_drift --n-points 8 --workers 8 --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.run --arms oracle_static --algos DenStream,CluStream --folds covtype,k_drift --seeds 1 --workers 8 --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.report --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.analyze --out-dir conf_pipeline/out/pilot
```

The oracle rerun reads `<out-dir>/oracle_static.json`, so it runs after the sweep. `analyze --full-out-dir <dir>` adds the capped-vs-full-length fidelity table.

**Notebook.** `otb_benchmark.ipynb` at the framework root runs all of the above top to bottom. It is generated by `python -m conf_pipeline.make_notebook`: edit the cells there, not the `.ipynb`. `OTB_PRESET` picks the preset: `tiny` (DenStream on `static_easy`, a smoke test in seconds), `pilot` (the default: DenStream, CluStream, HPStream, RepStream on 4 folds, seed 1) or `full` (8 algorithms x 18 folds x 5 seeds, oracle rerun on seeds 2-6). `OTB_OUT_DIR` overrides the output directory.

**Results** land in `conf_pipeline/out/<preset>/`: `runs.jsonl` (one summary row per job), `windows.jsonl` (one row per scored window), `members/` (one file per job, with `--log-members`), `sweep.jsonl` and `sweep_windows.jsonl`, `oracle_static.json`, and `report/` (`report.md`, `analysis.md`, CSVs, figures).

**Resume.** A job with a row on file is skipped whatever its status, so an interrupted command resumes by running it again; `--retry-failed` re-runs the jobs whose rows say `error`, `timeout` or `oom`. Each JSONL has a `.lock` file next to it (`runs.jsonl.lock`, `windows.jsonl.lock`, `sweep.jsonl.lock`) guarding against two writers; a driver that dies leaves them behind. Delete all of them, or pass `--force`, only once its process is gone.

**Where to run.** `tiny` and `pilot` run on a laptop. `full` goes on the Linux server, e.g. inside `tmux`: `OTB_PRESET=full .venv/bin/jupyter nbconvert --to notebook --execute otb_benchmark.ipynb --output otb_full_run.ipynb --ExecutePreprocessor.timeout=-1`. Copy its results back with `scp -r server:<repo>/conf_pipeline/out/full conf_pipeline/out/`; the report and analysis cells read them without rerunning anything.
