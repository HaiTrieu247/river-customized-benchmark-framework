# conf_pipeline

Online tuning and benchmarking of `river.cluster` in one pass. Every (algorithm, fold, seed) runs on one driver under three tuning regimes (*arms*): `default` (River's defaults, never changed), `confstream` (a confStream ensemble that re-picks its configuration by silhouette after every window) and `frozen_prefix` (tunes until window `FREEZE_AFTER_WINDOW`, then keeps its incumbent). `random_online` (the same ensemble, children drawn uniformly) left the protocol on 2026-10-12, as it cost about half the full budget; `--arms random_online` still runs it and the report still reads it. A Sobol sweep of fixed configurations picks a static oracle per (algorithm, fold), which is rerun as a fifth arm, `oracle_static`, to give the ceiling. Every quality number is the lagged ARI: the incumbent named after window t-1, scored on window t.

Run from the framework root (`--dry-run` lists the jobs; every protocol constant is a flag, see `--help`):

```bash
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.run --algos DenStream,CluStream --folds covtype,k_drift --seeds 1 --workers 8 --log-members --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.sweep --algos DenStream,CluStream --folds covtype,k_drift --n-points 8 --incumbents --workers 8 --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.run --arms oracle_static --algos DenStream,CluStream --folds covtype,k_drift --seeds 1 --workers 8 --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.report --out-dir conf_pipeline/out/pilot
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.analyze --out-dir conf_pipeline/out/pilot
```

The oracle rerun reads `<out-dir>/oracle_static.json`, so it runs after the sweep. The sweep runs after the arms: `--incumbents` adds, as fixed configurations rerun from the start with their exact parameters, the incumbent each online run held longest and its last one, so the ceiling is never below a configuration the online arms found (`oracle_static.json` and the report's `config_source` say whether the winner is the default, a Sobol point or an incumbent). The winner is picked on the tail, the region every arm is compared on (the whole stream when the stream has no tail; `select_metric` says which). `analyze --full-out-dir <dir>` adds the capped-vs-full-length fidelity table.

**Single-class windows.** A window whose true labels hold one class has no external reading: there ARI is 1 for a one-label prediction and 0 for any other, and purity is 1 whatever the prediction, so the number would reward a broken configuration. The driver records `ari_win`, `nmi_win`, `purity_win` and Table A's ARIs as None on such a window (`external_defined = False`, `_common.MIN_TRUE_CLASSES`), so it drops out of every mean, the oracle's pick included; the run row counts them (`n_single_class_windows`) and the windows the lagged ARI rests on (`lag_ari_n_windows`, `lag_ari_n_windows_tail`). kdd99's first 100 000 samples hold 71 such windows of 100.

**Reading the silhouette's cost.** `report` splits the gap to the ceiling twice. The primary split gives the labels the silhouette's one-window delay (`a_star_lag`, `R_proxy_lag`, `R_search_lag`); the same-window split (`a_star`, `R_lag`, `R_proxy`, `R_search`) picks the best member with the window's own labels, keeps that window's luck, and is a bound. `proxy.csv` is the per-window Spearman correlation between silhouette and ARI over the ensemble's members, given only where the members' ARIs spread by at least 0.05 within a window (`ari_spread`). `analyze` writes Kendall's tau twice: `kendall.csv` ranks a missing reading last, `kendall_complete.csv` compares only the algorithms both arms read; `degenerate.csv` counts per arm the cells whose configuration produced no usable partition.

**Implementation variant (T7).** `DenStreamPatchedFast` (DenStream with RIVER_BUGS.md BUG-7/BUG-8 fixed and the exact fast offline phase of GAP-3) runs through every arm like any algorithm, but `analyze` never ranks it with the others: `_common.IMPL_VARIANTS` maps it to `DenStream`, and `impl_table` / `report/impl_T7.csv` read it against DenStream per (arm, fold). The `full` preset includes it.

**KMeans `sigma`.** CluStream and STREAMKMeans tune the `sigma` their inner KMeans draws its initial centres from, in units of `s` (RIVER_BUGS.md GAP-5). Changing a search space invalidates earlier results of that algorithm: the manifest records every space, so a resume after the change is refused and the run goes into a fresh `--out-dir`.

**Robustness (A1-A5).** Two more commands ask how far the conclusions depend on the measure, the reference and the seeds, with no new tuning run. `python -m conf_pipeline.label_reach --out-dir <dir> --workers 8` runs, on every window of every fold, k-means and Ward with the true number of classes and DBSCAN with its radius chosen by ARI, on raw and on window-standardised features, into `label_reach.jsonl` (about 1.5 minutes for the 18 folds on 8 cores). These are label-informed references, not upper bounds: on most real folds some stream clusterer reads higher. `python -m conf_pipeline.robustness --out-dir <dir>` then writes `report/robustness.md` and `report/robustness/*.csv`: the capture ratio and the selection/search losses per stream group (`_common.stream_group`: real, parameter drift, other synthetic) with bootstrap intervals (folds within groups, then seed indices, the same for every arm; `--n-boot`, `--boot-seed`), the agreement of the rankings under ARI, NMI and purity, a reference selected on the even tail windows and read on the odd ones, Wilcoxon tests per algorithm with Holm's correction and rank-biserial effect sizes, the windows the single-class rule removes and the rankings without KDD99, and a table of the folds whose labels look usable (`--min-eval-windows`, `--min-reach-ari`: placeholders). It reads the published reference's tunable set and leaves every published table unchanged.

**Selection signals.** On real streams most of the gap to the reference is the silhouette picking the wrong member. `--signals silhouette_std,dbcv,dbcv_std,rank_agg[,stability]` (with `--log-members`) writes, for every member on every window, candidate label-free signals from `benchmark/tuning/signals.py` as `sig_<name>`: the silhouette after standardising the window with its own statistics, DBCV on raw and standardised features, a mean rank over silhouette, Calinski-Harabasz and Davies-Bouldin, and `stability`, the ARI between a member's predictions of the window before and after learning it (a second prediction pass, run on a deep copy because a prediction can change a River model, RIVER_BUGS.md BUG-7; asked for by name only). Logging never changes what the ensemble selects. `signals_runtime_s` in the window and run rows is what they cost: on a 12-job pilot of the cheaper algorithms on three real folds it was 2 to 7 minutes per run, 16% to 81% of the run's wall time, mostly DBCV. `python -m conf_pipeline.screen --out-dir <dir>` then reads the member logs and asks, per signal, what the tuner would have handed a user had it picked by that signal one window ahead, and which share of the silhouette's selection loss that wins back (`report/screen.md`). A signal that screens well is run as a signal arm, `--arms confstream_<signal>`, which selects by it throughout.

**Re-initialisation control.** `--arms frozen_reinit` freezes the parameters at `--freeze-after-window` like `frozen_prefix`, but keeps spawning `e_test` fresh models of the frozen configuration per window, warm-started and competing by silhouette as the tuner's children do. Compared with `confstream` and `frozen_prefix` after a drift, it separates the effect of renewing the model from that of changing the parameters.

**Tie-break.** When members tie on the score, the incumbent used to go to the faster one, and the measured runtime differs between two runs of one seed: on the full run 15% of the online regime's windows had such a tie whose members read different ARIs on the next window, so a rerun did not reproduce it exactly. Runs now break ties on fewer micro-clusters, then the incumbent, then the oldest member, which is deterministic (`--tie-break micro_clusters`, the default, recorded as `tie_break` in each run row). `--tie-break runtime` restores the old rule, for runs meant to sit beside `out/full`; the out dir's manifest records it, and a command with the other rule is refused there (see **Manifest**).

**CMM.** Every window also reads CMM (Kremer et al. 2011), the measure MOA evaluates stream clusterings with, for every member: `cmm_win` in the member logs, `lag_cmm_win` in the window rows, `lag_cmm_win_mean` and `lag_cmm_win_tail_mean` in the run rows, and A1 ranks the algorithms under it. `benchmark/evaluation/cmm.py` is a port of MOA's `CMM.java` and `CMM_GTAnalysis.java` (with the ground truth as `EvaluateClustering` builds it and `BatchCmd`'s point weights), and its tests hold every reading to MOA 2024.07.0's on 20 cases (`tests/fixtures/cmm_moa_cases.json`, which also keeps the Java harness). A cluster is the set of points given one label, and a River sentinel (DenStream's `-1`) leaves its point in no cluster. MOA's analysis merges classes whose points are connected and excuses a point that lies inside the sphere of the class its cluster maps to; on real windows that is most of them (all six INSECTS classes merge, `cmm_ca_separability` about 0.17; covtype keeps about a fifth of its classes apart), and MOA's CMM then reads 1 or close to it for every partition. `cmm_strict` is the same computation with both turned off, which separates partitions there but is not MOA's number, and is lenient with a one-label output on overlapping classes. `cmm_ca_separability` and `cmm_ca_model` (merged classes over classes, the share of points no other class's sphere holds) are read once per window; a single-class window has no CMM reading, as for the other external measures. The ground-truth analysis costs 8-17 ms per window of 1000 points (about 65 ms with 54 classes), each member's reading 0.3-0.4 ms; a 10-window pilot measured 0.2-0.7 s per run, under 7% of an online run but up to half of the cheapest default runs. `run --no-cmm` and `sweep --no-cmm` leave CMM out.

**A reference picked on several seeds.** Picked on seed 1 and reported on seeds 2-4, the reference sheds the optimism of a maximum only for the three algorithms that take a seed (CluStream, HPStream, STREAMKMeans); the other five read the same on every seed. `sweep --seeds 1,2,3` sweeps every configuration on each seed with one Sobol design (`--seed`) and picks the oracle on the mean, a configuration being eligible only with a reading on every seed (`_common.seed_means`); an algorithm that takes no seed is swept on the first seed alone. `oracle_static.json` records `select_seeds` and `select_sd`, and the oracle is then rerun on seeds of its own. To compare such a reference with the published one without touching `out/full`, build it in a directory of its own and hand that to `robustness`, which adds it to A2 as a construction read on all tail windows, never on a seed that picked it (a pair the directory lacks keeps the published reference, `reference_from`). The sweep's seed-1 rows can be reused, so only the new seeds run:

```bash
mkdir -p conf_pipeline/out/x5 && cp conf_pipeline/out/full/sweep.jsonl conf_pipeline/out/full/sweep_windows.jsonl conf_pipeline/out/x5/
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.sweep --out-dir conf_pipeline/out/x5 --seeds 1,2,3 --incumbents --incumbents-from conf_pipeline/out/full --workers 8 --adopt-legacy
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.run --out-dir conf_pipeline/out/x5 --arms oracle_static --seeds 4,5,6 --algos CluStream,HPStream,STREAMKMeans --workers 8
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.robustness --out-dir conf_pipeline/out/full --reference-dir multi_seed=conf_pipeline/out/x5
```

`--adopt-legacy` is needed once: the copied rows were made before manifests, and the manifest says their protocol is unknown. `--reference-dir NAME=DIR` takes any directory holding an `oracle_static.json` and its reruns, so a reference from another search fits the same table.

**Drift the study did not design.** `_common.X7_FOLDS` are eight streams outside `FOLDS`, run with `--folds` into a directory of their own. Four are real streams with natural drift (`benchmark/datasets/real/drift_streams.py`, downloaded and cached under `~/river_data` on first use): `rialto` (82 250 samples, 27 features, 10 classes), `sensor` (Intel Berkeley lab, 2.2 M readings in time order of which the cap keeps the first 27 hours, 4 features, 52 sensors as classes: two of the 54 never report every field), `insects_incremental_imbalanced` and `insects_incremental_reoccurring_imbalanced` (452 044 samples each). Four vary the parameter-drift design (`param_drift.DRIFT_VARIANT_SCENARIOS`): `scale_drift_x1_5` and `scale_drift_x8` jump the scale by 1.5 and 8 instead of 4, `random_drift` changes cluster count, radius and scale together at four points drawn at random off the window grid, and `scale_drift_gradual` spreads each change of `scale_drift` over a tenth of the stream along MOA's `ConceptDriftStream` sigmoid. The real ones report in the `real` group and the variants in `param_drift`. They are placeholders for the check, not a recommended set.

```bash
F=$(.venv/bin/python -c "from conf_pipeline import _common as C; print(','.join(C.X7_FOLDS))")
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.run --folds $F --out-dir conf_pipeline/out/x7 --log-members --workers 8
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.sweep --folds $F --out-dir conf_pipeline/out/x7 --incumbents --workers 8
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.run --folds $F --out-dir conf_pipeline/out/x7 --arms oracle_static --seeds 2,3,4 --workers 8
```

**Protocol constants.** `python -m conf_pipeline.variants run` changes one of `h`, `E`, `C`, `t0` at a time (`variants.VARIANTS`: each halved and doubled, the challengers kept at most half the ensemble; placeholders) and runs the three protocol arms of the six cheaper algorithms on seed 1 into `<out-dir>/<variant>/`, with the tie-break the base run recorded. `variants compare` writes `report/variants.md` and `variants.csv`: per stream group, every arm's mean tail ARI, the gain of online tuning, the capture ratio and Kendall's tau between arms, for the base run and every variant on the same seeds. A variant that keeps `h` and `t0` is read against the base run's reference (one fixed configuration that never meets `E` or `C`); one that changes them has no capture ratio unless `--own-reference` sweeps one in its directory.

```bash
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.variants run --out-dir conf_pipeline/out/x6 --base-dir conf_pipeline/out/full --workers 8
PYTHONHASHSEED=0 .venv/bin/python -m conf_pipeline.variants compare --out-dir conf_pipeline/out/x6 --base-dir conf_pipeline/out/full
```

**Where the jobs ran.** Every `run` or `sweep` command that runs jobs appends to `<out-dir>/environment.jsonl` the time, its arguments, and the machine and software it ran on (`benchmark.reports.capture_environment`, now with the CPU model and memory read from the system). `report` lists each distinct machine once under "Where the jobs ran" and in `environment.csv`; results made before 2026-10-23 have no record.

**Notebook.** `otb_benchmark.ipynb` at the framework root runs all of the above top to bottom. It is generated by `python -m conf_pipeline.make_notebook`: edit the cells there, not the `.ipynb`. `OTB_PRESET` picks the preset: `tiny` (DenStream on `static_easy`, a smoke test in seconds), `pilot` (the default: DenStream, CluStream, HPStream, RepStream on 4 folds, seed 1) or `smoke` (every algorithm and fold of `full`, seed 1, arms default and confstream, 25 000 samples: catches load and algorithm failures and measures cost on the cells the pilot never ran, before `full`) or `full` (8 algorithms + DenStreamPatchedFast x 18 folds x 3 seeds x 3 arms, oracle rerun on seeds 2-4). `OTB_OUT_DIR` overrides the output directory.

**Results** land in `conf_pipeline/out/<preset>/`: `runs.jsonl` (one summary row per job), `windows.jsonl` (one row per scored window), `members/` (one file per job, with `--log-members`), `sweep.jsonl` and `sweep_windows.jsonl`, `oracle_static.json`, and `report/` (`report.md`, `analysis.md`, CSVs, figures).

**Resume.** Before anything else a command checks the out dir's manifest (see **Manifest**). A job with a row on file is skipped whatever its status, so an interrupted command resumes by running it again; `--retry-failed` re-runs the jobs whose rows say `error`, `timeout` or `oom`. Each JSONL has a `.lock` file next to it (`runs.jsonl.lock`, `windows.jsonl.lock`, `sweep.jsonl.lock`) guarding against two writers; a driver that dies leaves them behind. Delete all of them, or pass `--force`, only once its process is gone.

**Where to run.** `tiny` and `pilot` run on a laptop. `full` goes on the Linux server, e.g. inside `tmux`: `OTB_PRESET=full .venv/bin/jupyter nbconvert --to notebook --execute otb_benchmark.ipynb --output otb_full_run.ipynb --ExecutePreprocessor.timeout=-1`. Copy its results back with `scp -r server:<repo>/conf_pipeline/out/full conf_pipeline/out/`; the report and analysis cells read them without rerunning anything.

**Manifest.** Resume keys (algo, fold, seed, arm, cap, config) name none of the constants a job ran under, so a command with other flags pointed at an existing out dir used to skip every job it found. Every `run` and `sweep` that runs jobs now writes `<out-dir>/manifest.json` (`conf_pipeline/manifest.py`) and checks it first, dry runs included: the shared protocol (window, cap, half-life, feasibility caps, `t0`, CMM, the data-generator seed `--data-seed`) and module constants must match exactly; every arm's effective ensemble configuration, every algorithm's factory, River defaults, pinned values and search space, and every stream's source, order, cap and data seed must match where they are already on file, and new ones extend the dir (more seeds, another arm or fold stay legal); the sweep's Sobol seed must match (more points extend the design, which is prefix-stable). A hash of the content of the Python files under `benchmark/` and `conf_pipeline/` and of River (`code.code_sha256`), and one of the installed packages, block a resume when they differ, unless `--allow-code-change`, which the manifest's `history` records; the commits and uncommitted changes are recorded beside them, and a new commit of the same code or an edited document is no change. Every child reports the hash of the code it imported (`code_sha256` on its run row), so a command whose code is edited while it runs stops before writing the first row made by other code. The manifest is locked (`manifest.json.lock`) for the whole command and checked again once the lock is held, so a second `run` or `sweep` into the same dir is refused while one runs (`--force` overrides it, as for the result files' locks). Each child hashes the samples it consumed (`stream_sha256` on its run row); the first hash of a stream is recorded and a later run that saw other content stops the command before its row is written. Every summary row carries `protocol_fingerprint` and `job_fingerprint`. A dir holding results but no manifest (every dir made before 2026-10-23, `out/full` included) is refused unless `--adopt-legacy`, which records that the earlier rows' protocol is unknown; `python -m conf_pipeline.manifest describe --out-dir <dir>` writes, without touching the dir's results, `report/provenance.{json,md}`: the hash of every file and, per arm, the values the ok run rows recorded (`<absent>` where a row predates a field), and "unknown" for the rest.

**Repeatability.** The deterministic tie-break does not make a run repeatable: the runtime cap sheds a member against the fastest one of the window, and measured time follows the machine's load. `--no-runtime-gate` (on `run` and `sweep`) never sheds a member for its runtime; memory, micro-cluster and timeout limits still apply, and every member's `runtime_ratio` against the window's fastest partitioning member is logged, so a cap can be replayed afterwards. Member rows and window rows carry `pred_sha`, a hash of the predictions on the window, and the window and run rows split the wall time into the models (`ensemble_runtime_s`), the silhouettes (`scoring_runtime_s`), building and warm-starting challengers (`spawn_runtime_s`), calibration, CMM, signals, Table A and the member log. `python -m conf_pipeline.repeat --a DIR --b DIR` compares two runs of one protocol window by window and names, per job, the first window and field where they part and why (`runtime gate`, `model or scoring`, `sampling`, `tie-break`, `not logged`). On a 12-job smoke on one laptop (`out/repeat_smoke/report/SUMMARY.md`: six of the cheaper algorithms, two folds, 20 000 samples, seed 1) a second run under another load diverged in 7 of 12 jobs with the cap on, every one through the cap, the tail ARI moving by up to 0.40; with `--no-runtime-gate` all 12 repeated exactly. Repeating across machines, and with CluStream and RepStream, is not yet checked. The gate-free mode is a different protocol from the full run's and is compared with it as a sensitivity.

**Selection regret (P1.1).** `conf_pipeline/selection.py` turns the disagreement between the default and the online-tuning rankings into what it costs to choose an algorithm. On each fold it picks the algorithm that is best under the selecting arm (`--selecting-arm`, River's defaults by default) and reports the regret: the best tail ARI under the target regime minus the pick's tail ARI under it (`confstream`; `frozen_prefix` and `oracle_static` as sensitivity targets), with top-1 agreement, top-k overlap and Kendall's tau-b. Ties are a uniform pick with best and worst cases; a practical-effect band (`--band`, `MIN_CEILING_GAIN` by default) treats algorithms within b of the top as tied and gives the share of folds losing more than b. It compares with a random pick and with global choices made on the other source blocks (leave-one-block-out, by mean score and by mean rank), aggregated per stream group and source block, fold- and block-weighted, with their denominators. The same-data number is a descriptive selection regret; two out-of-sample variants split by seeds (`--select-seeds`, `--eval-seeds`) and by time (the first and second half of each run's tail). `python -m conf_pipeline.selection --out-dir <dir>` writes `report/selection/` (another selecting arm: `report/selection_<arm>/`).

**Statistical unit and metric sensitivity (P1.2).** `robustness` also writes a P1.2 section of `robustness.md` and its CSVs. `conclusions.csv` crosses every conclusion (online minus default, frozen_prefix and the reference, the capture ratio of both deployable arms, the selection and search losses and the selection share, Kendall's tau between arms) with the measure (ARI, NMI), the statistical unit (`fold`, or `block`: `_common.source_block`, so the INSECTS variants count as one source) and the reference construction: the published ARI-selected reference and its even/odd variant; (a) "ARI-selected reference, NMI-evaluated", every ARI selection read in NMI; (b) "NMI-reselected reference", the reference and the labels' pick re-chosen by NMI over the same candidates, an in-sample maximum over a finite set, not an NMI optimum. Model seeds never add units; the protocol arms are paired by seed and the reference's reruns drawn apart. Every ratio carries numerator, denominator and n; a per-pair denominator at most `--min-denominator` (0.01, a placeholder) reads undefined and nothing is clipped. `paired_effects.csv` gives per-algorithm effects with Wilcoxon over units and Holm; `loo.csv` leaves out one stream or one source block. Most checks `result/otb_full/report/make_robustness_extra.py` printed are functions of `robustness` now; four of its sections are not ported (the silhouette on single-class windows, the `-1` sentinels, the tie-break replay and the recovery after drift). `python -m conf_pipeline.robustness_check --out-dir conf_pipeline/out/full --published result/otb_full/report/robustness_extra.txt` recomputes the ported ones against the printed numbers (362 of 362 match, the unported sections listed).

**Screening on paired supports.** Beside its own-support tables, `screen` reads every logged signal on two supports that are the same windows for all signals: `common` (the tail windows where labels, the silhouette and every logged signal picked; the only support on which recovery ratios compare signals without imputation) and `fallback` (a signal that picked nobody takes the silhouette's pick). `screen/support_groups.csv` and `support_pairs.csv` give pair coverage, windows compared, the signal-defined rate, the absolute ARI gain over the silhouette's pick and the recovery ratio with numerator and denominator; `missing.csv` says why a signal picked nobody, `cost.csv` the signals' share of wall time (one timer covers all logged signals, so there is no per-signal cost), `pick_log.csv` the per-window evidence. The section is labelled exploratory: streams screened are development data for the choice of a signal. `run --signal-noise label|drop|singleton` (`signals.NOISE_POLICIES`) sets how the signals read a model's sentinel label: as a cluster (the default, the tuner's own silhouette's reading), left out, or one cluster per point (DBCV's handling of noise in the paper). No independent DBCV implementation is installed; `tests/test_tuning_signals.py` holds a comparison with `hdbscan` that runs where it is, and DBCV depends on how the minimum spanning tree breaks ties between equal mutual-reachability distances (`signals.dbcv`'s docstring).

**Scaled defaults (E1).** `--arms scaled_default` runs River's defaults, as `start_params` sets them (pinned values, buffers clamped to `h`), with each absolute-distance parameter multiplied by the distance unit `s` (`spaces.distance_params`: the spaces' `scaled` dimensions; `scaled_defaults`): DenStream's `epsilon`, DBSTREAM's `clustering_threshold`, SOStream's `merge_threshold`, BIRCH's `threshold` (0, which stays 0) and the `sigma` of CluStream's and STREAMKMeans' inner KMeans (1, KMeans' own default). It is one fixed configuration, never tuned, recorded with `scaled_params`; HPStream and RepStream have no such parameter and are written down as skipped rather than rerun, and BIRCH's scaled default equals its default (0 times `s`), so three of the eight algorithms read the same as under the defaults. One `s` changes neither one feature's scale against another's nor a translation.

**Oracle-signal tuner (E4).** `--arms confstream_ari_oracle` is a diagnostic tuner, never a deployable one: every selection (incumbent, victims, parents) is made by the ARI of the window just processed, read one window later as the silhouette's picks are; a window with fewer than two true classes reads nothing and the incumbent stays. `confstream_ari_oracle_constrained` keeps the silhouette's gate (a member without a partition stays undefined). `report`, `analyze` and the other default readers leave both out (`report.current_runs` and `load_windows` read them only with `diagnostic=True`), so no table, ranking or normalisation of the deployable arms moves when they share a dir. `python -m conf_pipeline.oracle_compare --out-dir <dir>` pairs, on the same tail windows, the silhouette's tuner, the labels' pick within its ensemble (needs `--log-members`) and every oracle arm the dir holds, and reports the signed differences, which are operational comparisons, not a causal split into signal and search. The labels' pick keeps the silhouette's gate, so the constrained oracle is the like-for-like comparison of the search (`like_for_like`).

**Cost of a planned run.** `python -m conf_pipeline.cost --from conf_pipeline/out/full --algos ... --folds ... --arms ... --seeds ... --workers N` projects CPU hours and wall time from the measured wall time of the same (algo, fold, arm), scaled by the sample cap and `--factor`; an arm never measured is read through `--proxy arm=measured_arm`, printed as an assumption, and an unmeasured cell is counted, not guessed.

**Seeds.** Since 2026-10-24 an out dir runs under the `split` seed policy by default (`docs/SEED_RULES.md`): `--tuner-seeds` (101, 102, 103) seed the tuner's draws, `--model-seed` (201, one per out dir) the models of the online arms (CluStream, HPStream and STREAMKMeans take a seed), `--fixed-model-seeds` the repeats of a fixed configuration of those three, and the subsample the distance unit is estimated on has a constant seed of its own, so every arm reads the stream in the same unit. A fixed configuration draws nothing from a tuner: for the five deterministic algorithms it runs once (`run.job_seeds`), and the reports set its mean beside every tuner seed without counting it as several observations (`report.replicate_view`; `summary` says what each arm's runs vary in, `replicates`, and how many there are, `n_runs`). Every row records `seed_policy`, `tuner_seed`, `model_seed` and `calibration_seed`. The sweep takes `--sobol-seed` and `--model-seeds`, and `run --arms oracle_static` refuses to rerun the reference on a model seed that picked it. `--seed-policy shared --seeds ...` is the policy of every run made before (one job seed for tuner, models and calibration), kept to run beside `out/full`: `otb_benchmark.ipynb` and the X6 variants use it, and a fixture captured from the code before the split holds it to what it produced.
